# 策略 B · 初步软件需求（一次性输出）

> 生成方式：学生一次性陈述 + 大模型单轮审查补全
> 说明：本版本保留模型默认假设，未做二次澄清

## 1. 软件背景

在校园记账系统上增加共享账本，面向宿舍、社团、旅行、聚餐等多人消费场景。用户创建账本并邀请成员，成员共同记录支出，系统自动分摊并计算欠款，最终完成结算。

## 2. 欲解决的问题

多人共同消费时，记录分散、分摊靠手算、结算不清楚。共享账本把流水集中管理，自动计算每个人的应付和垫付，减少对账成本。

## 3. 软件解决方案

- 账号登录后创建账本，通过链接邀请成员；
- 成员记录支出，填写付款人和参与人；
- 系统按均分、比例或金额分摊；
- 系统计算净余额，生成结算建议；
- 结算后标记已还，账本内提供统计和导出。

## 4. 范围与边界

**范围内**：账号、账本、成员、支出、分摊、结算、统计、预算、提醒、导出、智能录入。

**范围外**：无明确排除项（模型未主动限制范围，仅将真实支付视为后续能力）。

## 5. 利益相关方

| 利益相关方 | 主要诉求 |
|---|---|
| 学生用户 | 快速记账、自动算账 |
| 创建者 | 管理账本、邀请成员 |
| 开发者 | 复用现有技术栈，快速实现 |
| 运维 | 数据安全和可恢复 |

## 6. 功能性需求

| 编号 | 需求名称 | 描述 | 优先级 |
|---|---|---|---|
| FR-B-01 | 账号 | 支持注册、登录、退出、找回密码 | P0 |
| FR-B-02 | 创建账本与邀请 | 登录用户创建账本，生成永久有效的邀请链接，可多人使用，人数不设上限 | P0 |
| FR-B-03 | 加入账本 | 访客通过邀请链接注册/登录后加入账本 | P0 |
| FR-B-04 | 记录支出 | 记录金额、分类、日期、付款人、参与人、备注 | P0 |
| FR-B-05 | 自动分摊 | 支持均分、按比例、按金额分摊，保留两位小数 | P0 |
| FR-B-06 | 余额与结算 | 自动计算每人净额，生成“谁欠谁”的结算建议，结算后可标记已还 | P0 |
| FR-B-07 | 修改与删除 | 所有成员可编辑和删除任意记录；删除后不可恢复 | P0 |
| FR-B-08 | 成员退出 | 成员可随时退出账本，退出后其未结清余额自动清零 | P0 |
| FR-B-09 | 统计 | 查看账本总额、分类统计和成员统计 | P1 |
| FR-B-10 | 预算与提醒 | 设置账本月预算，超支时提醒全体成员；支持站内提醒和微信服务号推送 | P1 |
| FR-B-11 | 导出 | 导出账本流水为 CSV 和 JSON | P1 |
| FR-B-12 | 智能录入 | 支持 OCR 识别小票、语音记账、自动导入支付宝/微信账单 | P1 |
| FR-B-13 | 微信支付 | 接入微信支付，实现自动扣款和自动对账 | P2 |
| FR-B-14 | 区块链存证 | 账目上链，保证不可篡改 | P2 |

## 7. 非功能性需求

| 编号 | 类别 | 需求描述 |
|---|---|---|
| NFR-B-01 | 性能 | 页面响应快，流水多时不卡顿 |
| NFR-B-02 | 安全 | 全站 HTTPS，密码加密存储，权限服务端校验 |
| NFR-B-03 | 隐私 | 账本默认公开可搜索；同时只有账本成员能查看账本内容 |
| NFR-B-04 | 易用性 | 操作简单，新用户无需培训 |
| NFR-B-05 | 兼容性 | 支持主流桌面和移动浏览器 |
| NFR-B-06 | 可靠性 | 系统稳定，数据不丢失 |

## 8. 约束

1. 沿用 Electron + Vue3 + FastAPI + SQLite；
2. 人民币记账，金额两位小数；
3. 中文界面；
4. 课程项目，6–8 周完成；
5. 邀请链接永久有效，不设人数上限。
