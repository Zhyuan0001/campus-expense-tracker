# 策略 A · 初步软件需求（访谈式输出）

> 生成方式：12 轮访谈后由大模型汇总
> 说明：本版本尽量保留访谈中的原始结论，尚未经过跨策略评审

## 1. 软件背景

在任务01校园记账系统 v3.1.0 的基础上扩展共享账本能力。现有系统是单用户本地记账应用，支持个人记账、分类统计、预算、导出和备份；v4.0 面向宿舍、社团、旅行、聚餐等多人共同消费场景，解决记录分散、分摊易错、结算不清的问题。

## 2. 欲解决的问题

1. 共同开销散落在微信群、Excel 和截图中，容易漏记、重记；
2. 谁垫付、谁参与、谁该付多少，靠记忆和手算，容易出错；
3. 多人互相欠款时，转账链路长，结清状态不透明；
4. 社团经费多人经手，缺少权限控制和操作留痕；
5. 共同开销混入个人账本，导致个人统计和预算失真。

## 3. 软件解决方案

- 建立账号与共享账本，账本成员共同维护流水；
- 每笔支出记录付款人、参与人、分摊方式，系统自动计算应付与垫付；
- 系统计算净余额并生成转账建议，双方确认后结清；
- 用角色权限和审计日志保证多人协作可追溯；
- 个人账本与共享账本分开统计，互不污染；
- 平台只记录账目和结清状态，不实际转移资金。

## 4. 范围与边界

**范围内**：账号、账本、成员与角色、共同支出、分摊、退款、结算、统计、共享预算、站内提醒、导出备份、审计日志。

**范围外**：真实支付、第三方账单自动导入（访谈中未确认，见第 8 节）、OCR、语音记账、多币种、公开社交、短信/邮件推送、离线写入、社团报销审批、运营后台。

## 5. 利益相关方

| 利益相关方 | 主要诉求 |
|---|---|
| 普通成员 | 快速记账、看清自己应付和垫付 |
| 账本创建者 | 管理成员、对账、导出、追溯 |
| 账本管理员 | 协助管理成员和记录，权限受创建者约束 |
| 被邀请者 | 低门槛加入并查看历史 |
| 开发与运维 | 需求可验证、系统可维护可恢复 |
| 学校/监管 | 个人信息最小化收集、可删除 |

## 6. 功能性需求

| 编号 | 需求名称 | 描述 | 优先级 | 验收要点 |
|---|---|---|---|---|
| FR-A-01 | 账号 | 支持注册、登录、退出、找回密码 | P0 | 未登录不能访问账本；密码错误 5 次锁定 10 分钟 |
| FR-A-02 | 个人资料 | 维护昵称、头像；手机号和邮箱默认仅自己可见 | P1 | 其他成员看不到联系方式 |
| FR-A-03 | 创建账本 | 登录用户可创建账本，填写名称、类型、默认分摊方式 | P0 | 创建者自动成为 Owner |
| FR-A-04 | 邀请成员 | 创建者/管理员生成 6 位邀请码和链接，7 天有效，可撤销，可多人使用 | P0 | 过期或撤销后不能加入；账本上限 50 人 |
| FR-A-05 | 加入账本 | 访客通过邀请链接注册/登录后加入，可查看加入前的历史流水 | P0 | 重复加入不产生重复成员 |
| FR-A-06 | 成员管理 | 创建者可设/撤管理员、移除成员、转让创建者；管理员可移除普通成员；成员可随时退出，未结清余额由创建者承接 | P0 | 管理员不能移除管理员或 Owner |
| FR-A-07 | 新增共同支出 | 记录金额、分类、备注、日期、付款人、参与人、分摊方式、凭证图片 | P0 | 付款人/参与人必须是成员；金额 > 0；日期不晚于今天且不早于一年前 |
| FR-A-08 | 分摊计算 | 支持均分、按金额、按比例；金额精确到分，余数优先给付款人，付款人不参与时给第一位参与人 | P0 | Σ应付 = 支出金额；比例合计 100%；金额合计等于总额 |
| FR-A-09 | 编辑/删除支出 | 记录创建者 24 小时内可改；Owner/管理员可改任意记录；删除二次确认并软删除；已结算记录不可改删 | P0 | 每次修改写审计日志 |
| FR-A-10 | 退款 | 支持整单退款，按原分摊比例冲销；退款后原支出锁定 | P1 | 退款金额等于原支出；重复退款被拒绝 |
| FR-A-11 | 流水查看 | 按月份、分类、成员、关键字筛选流水，显示付款人、参与人、分摊明细 | P0 | 500 条流水下列表可正常筛选 |
| FR-A-12 | 结算方案 | 系统计算每人净额，生成“谁转给谁、转多少”的转账建议 | P0 | 20 人账本转账笔数不超过 19 笔 |
| FR-A-13 | 结清确认 | 付款方标记已转账，收款方确认到账；支持部分结清；有争议可拒绝，状态回退 | P0 | 双方确认后才算结清 |
| FR-A-14 | 账本统计 | 按月/分类/成员统计支出、垫付、应付；区分个人账本与共享账本 | P1 | 统计口径与流水一致 |
| FR-A-15 | 共享预算 | Owner/管理员设置账本月度预算，达到 80%/100% 时提醒 | P1 | 未设置预算时不提醒 |
| FR-A-16 | 导出/备份 | 普通成员导出自己的流水；Owner/管理员导出全账本 CSV/JSON | P1 | 导出内容与页面口径一致 |
| FR-A-17 | 站内提醒 | 新支出、待结算、预算超支在站内提醒；结算提醒可通过微信服务号推送 | P2 | 提醒可标记已读 |
| FR-A-18 | 审计日志 | 记录新增、修改、删除、退款、成员变更、结算确认等关键操作 | P1 | 日志保留至少 180 天，仅 Owner/管理员可查 |
| FR-A-19 | 第三方账单导入 | 支持导入微信/支付宝账单，自动匹配分类 | P2 | 导入后可编辑、可撤销 |

## 7. 非功能性需求

| 编号 | 类别 | 需求描述 |
|---|---|---|
| NFR-A-01 | 性能 | 账本首页 1 秒内打开；500 条流水列表 1 秒内完成筛选；20 人结算计算 2 秒内完成 |
| NFR-A-02 | 可靠性 | 系统可用性 99%；任何故障不得丢失已确认支出；故障后 10 分钟内恢复 |

| NFR-A-04 | 隐私 | 非成员不可查看账本；个人账本互不可见；联系方式默认隐藏；支持导出和删除个人数据 |
| NFR-A-05 | 易用性 | 熟练用户 30 秒完成一笔支出；新用户 5 分钟完成“加入—记账—看结算”；适配 360px 宽度 |
| NFR-A-06 | 兼容性 | Windows 10+、Android 10+、iOS 15+、Chrome/Edge 最近两个大版本 |
| NFR-A-07 | 可维护性 | 前后端分离，接口版本化；关键操作日志保留 180 天 |
| NFR-A-08 | 一致性/并发 | 分摊金额合计必须等于支出金额；同一记录并发修改时，后保存方收到冲突提示 |

## 8. 约束

1. 沿用 Electron + Vue 3 + TypeScript + FastAPI + SQLite；
2. 仅支持人民币，金额两位小数；
3. 日期按 Asia/Shanghai，不允许未来日期，最早补记一年前；
4. 在线写入，离线仅可查看缓存；
5. 不接真实支付、短信、邮件服务；
6. 课程项目周期 6–8 周，团队约 3 人。

## 9. 建议但未确认

以下内容为访谈助理根据经验补充，访谈中**没有形成明确共识**，进入验证阶段处理：

1. **微信/支付宝账单自动导入**（FR-A-19）：学生只说过“希望少手动输入”，没有确认接口和授权方式；
2. **微信服务号推送**（FR-A-17）：学生明确说过“不做短信/邮件推送”，微信推送属于同一类外部服务，需要确认是否保留；
3. **AI 自动分类**：访谈中学生说“以后再说”，本版本未列入功能需求。

## 10. 待确认问题

2. 邀请是否需要创建者审批？
3. 归档账本能否恢复？恢复后是否可编辑？

5. 凭证图片的格式、大小和保存期限？
