# 策略 C · 多 Agent：提示词与使用说明

## 1. 交互环境

- 平台：Qoder
- 日期：2026-10-20
- 形式：同一会话内依次切换三个角色，共 3 个阶段
- 目的：用多视角交叉检查，观察是否能发现单 Agent 遗漏的矛盾和边界

## 2. 编排提示词

```text
接下来你将依次扮演三个 Agent，完成共享账本的需求获取。每个阶段结束时暂停，
等我确认后再进入下一阶段。三个 Agent 的职责必须严格分开：

Agent 1 用户代理：分别扮演宿舍长、普通成员、社团财务，提出各自视角的诉求；
Agent 2 分析师代理：合并三方诉求，形成初步需求与用例，标注来源和冲突裁决；
Agent 3 评审代理：只挑错，不重写需求，从完整性、一致性、可行性、可测试性、
范围控制五个维度输出问题清单。
```

## 3. Agent 1 · 用户代理提示词

```text
你是用户代理。请分别以三个角色发声，每个角色单独一节，不要合并：
1. 宿舍长：负责收水电费、组织聚餐，想快速建账和催款；
2. 普通成员：只想记自己的账、看清应付，不想被频繁打扰；
3. 社团财务：多人经手经费，需要权限、审计和期末导出。

每个角色请回答：
- 你最常遇到的 3 个问题；
- 你希望系统必须有的 3 个功能；
- 你最不能接受的事情；
- 你能接受的复杂度和提醒频率。
不要替其他角色说话，不要给技术方案。
```

## 4. Agent 2 · 分析师代理提示词

```text
你是需求分析师。请合并上一阶段三个角色的诉求：
1. 去重并保留来源角色；
2. 对角色之间的冲突给出裁决建议，并说明理由；
3. 形成初步需求（功能需求 FR-C-xx、非功能需求 NFR-C-xx、约束）；
4. 形成用例信息（参与者、用例名称、描述、前置条件、后置条件）；
5. 明确哪些需求属于 v4.0，哪些应延后。
不要新增三个角色都没提过的功能；如果必须补全，单独标注“分析师补充”。
```

## 5. Agent 3 · 评审代理提示词

```text
你是需求评审代理。不要重写文档，只输出问题清单。
请从以下维度审查：
- 完整性：是否遗漏关键场景、角色、异常；
- 一致性：需求之间、需求与用例之间是否矛盾；
- 可行性：技术、成本、进度、合规是否可行；
- 可测试性：每条需求是否能被客观验证；
- 范围控制：是否有超出 v4.0 边界的过度设计。
每个问题给出：编号、严重度（高/中/低）、位置、问题描述、修改建议。
```

## 6. 使用说明

- 三阶段均由同一个大模型扮演，但通过角色隔离避免“自己审自己”；
- 学生只做裁决，不干预各 Agent 的独立输出；
- 评审代理的意见在 `04-评审意见.md` 中保留，最终是否采纳由学生决定。
