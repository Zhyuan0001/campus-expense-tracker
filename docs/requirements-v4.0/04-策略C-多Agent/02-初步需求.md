# 策略 C · 初步软件需求（多 Agent 输出）

> 生成方式：用户代理（三视角）→ 分析师代理合并 → 评审代理挑错
> 说明：本版本保留评审前的 P2 候选需求，便于对比“全面”与“过度设计”的边界

## 1. 软件背景

在校园记账系统上增加共享账本，面向宿舍、社团、旅行、聚餐等多人消费场景。系统覆盖账号、账本、成员角色、共同支出、分摊、退款、结算、统计、预算、提醒、导出和审计。

## 2. 欲解决的问题

1. 共同消费记录分散，漏记、重记；
2. 分摊规则混用，手算易错；
3. 多人欠款链路长，结清状态不透明；
4. 多人经手缺少权限与审计；
5. 个人账与共同账混在一起，统计失真。

## 3. 软件解决方案

- 账号 + 共享账本 + 角色权限；
- 支出记录付款人、参与人、分摊方式，系统自动计算；
- 净额结算，双方确认；
- 关键操作审计，数据可导出；
- 个人账本与共享账本隔离。

## 4. 范围与边界

**v4.0 范围内**：账号、账本、成员与角色、支出、分摊、退款、结算、统计、预算、提醒、导出、审计、账号注销。

**v4.0 范围外**：报销审批、真实支付、第三方账单导入、OCR、语音、多币种、公开社交、短信/邮件推送、离线写入。

**候选/待定**：多端实时协同、校园卡对接、最优结算算法、多租户隔离（评审后处理）。

## 5. 利益相关方与角色

| 角色 | 说明 | 核心诉求 |
|---|---|---|
| 访客 | 未登录/未加入 | 低门槛加入 |
| 普通成员 | 账本参与者 | 看清应付、垫付、结算 |
| 管理员 Admin | Owner 授权 | 协助管理成员和账目 |
| 创建者 Owner | 账本所有者 | 管人、管账、导出、审计 |
| 系统 | 被动参与者 | 计算、提醒、审计 |
| 运维 | 系统管理员 | 安全、备份、恢复 |

## 7. 非功能性需求

| 编号 | 类别 | 需求描述 |
|---|---|---|
| NFR-C-01 | 性能 | 账本首页 1s 内打开；500 条流水筛选 1s 内完成；20 人结算 2s 内完成 |
| NFR-C-02 | 可靠性 | 可用性 99%；已确认支出不丢失；故障后 10 分钟内恢复 |
| NFR-C-03 | 安全 | HTTPS；密码加盐哈希；登录与邀请码限流；权限服务端校验 |
| NFR-C-04 | 隐私 | 非成员不可查看账本；个人账本互不可见；联系方式默认隐藏；支持导出与删除 |
| NFR-C-05 | 易用性 | 30 秒完成一笔支出；新用户 5 分钟完成主流程；适配 360px 宽 |
| NFR-C-06 | 兼容性 | Windows 10+、Android 10+、iOS 15+、Chrome/Edge 最近两个大版本 |
| NFR-C-07 | 可维护性 | 前后端分离、接口版本化、审计日志 180 天 |
| NFR-C-08 | 一致性/并发 | 分摊合计 = 支出金额；并发修改采用版本号冲突提示 |
| NFR-C-09 | 多租户与灰度 | 支持多租户隔离与灰度发布 | 

## 8. 约束

1. 沿用 Electron + Vue3 + TypeScript + FastAPI + SQLite；
2. 人民币记账，金额两位小数；
3. 日期按 Asia/Shanghai，不允许未来日期，最早补记一年前；
4. 在线写入，离线只读；
5. 不接真实支付、短信、邮件；
6. 课程项目 6–8 周，3 人团队。
