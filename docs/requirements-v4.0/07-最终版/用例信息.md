# 搭子账本 v4.0 · 校验后的用例信息

> 用例编号与 `初步软件需求.md` 中的 FR 编号对应；每个用例均包含参与者、名称、描述、前置条件、后置条件。

## 1. 参与者

| 参与者 | 类型 | 说明 |
|---|---|---|
| 访客 Guest | 主动 | 未登录或未加入账本的用户 |
| 普通成员 Member | 主动 | 已加入账本的成员 |
| 管理员 Admin | 主动 | 由 Owner 授权，可管理普通成员和账目 |
| 创建者 Owner | 主动 | 账本最高权限持有者 |
| 系统 System | 被动 | 计算分摊、余额、提醒、审计 |

**泛化关系**：Owner 继承 Admin，Admin 继承 Member。

## 4. 关键用例详述

### 4.1 UC-07 记录共同支出

- **参与者**：普通成员
- **描述**：成员记录一笔多人共同支出，指定付款人、参与人和分摊方式，系统计算每人应付并更新余额。
- **前置条件**：用户已登录且是账本成员；账本未归档。
- **后置条件**：支出记录创建成功；每人分摊金额已写入；账本净额更新；操作写入审计日志。
- **主流程**：
  1. 成员点击“记一笔”；
  2. 输入金额、选择分类、填写备注（≤100 字）和日期；
  3. 选择付款人（默认自己）和参与人（默认全体成员，可取消勾选）；
  4. 选择分摊方式，系统实时显示每人应付；
  5. 可选上传最多 3 张凭证；
  6. 提交，系统校验金额、日期、成员资格和分摊合计；
  7. 保存成功，流水和余额刷新，相关成员收到站内提醒。
- **异常流程**：
  - 金额 ≤0、超过 1,000,000 或超过两位小数：拒绝保存；
  - 参与人为空或包含非成员：拒绝保存；
  - 分摊合计不等于总额：提示差额，拒绝保存；
  - 日期晚于今天或早于 365 天前：拒绝保存；
  - 凭证格式或大小不符：拒绝上传；
  - 网络中断：不保存，提示重试；重复提交由幂等键拦截。

### 4.2 UC-08 设置分摊

- **参与者**：普通成员
- **描述**：为支出选择分摊方式，系统按规则计算每位参与人的应付金额。
- **前置条件**：正在新增或编辑支出；参与人已确定。
- **后置条件**：每位参与人的应付金额确定，合计等于支出金额。
- **主流程**：
  1. 选择均分/按金额/按比例；
  2. 均分：系统按人数平分，余数按“付款人优先，其余按参与顺序”逐分分配；
  3. 按金额：用户输入每人金额，系统校验合计；
  4. 按比例：用户输入每人比例（最多两位小数），系统校验合计 100%；
  5. 系统展示分摊预览；
  6. 确认后进入保存。
- **异常流程**：
  - 按金额合计不等于总额：提示差额；
  - 按比例合计不等于 100%：提示差额；
  - 任一参与人分摊 ≤0：提示调整；
  - 修改参与人后：重新计算，要求用户确认。

### 4.3 UC-12 生成结算方案

- **参与者**：普通成员
- **描述**：系统按成员汇总已付、应付和净额，生成转账建议。
- **前置条件**：是账本成员；存在未结清余额。
- **后置条件**：展示转账方案；方案可追溯到支出明细。
- **主流程**：
  1. 成员进入结算页；
  2. 系统计算每位成员的已付、应付、净额；
  3. 校验净额合计为 0；
  4. 将净欠款成员和净应收成员分别排序；
  5. 贪心匹配：净欠款最多者向净应收最多者转账，金额取两者绝对值较小者；
  6. 重复直到所有净额归零；
  7. 展示转账列表和总笔数（≤ 成员数 − 1）。
- **异常流程**：
  - 净额合计不为 0：中止并提示数据异常；
  - 存在已退款/已删除记录：按冲销后净额计算；
  - 并发新增支出：提示刷新后重新生成。

### 4.4 UC-13 确认结清

- **参与者**：付款方、收款方
- **描述**：付款方线下转账后标记“已转账”，收款方确认到账或拒绝，完成一笔结算。
- **前置条件**：存在待结清转账；双方均为账本成员。
- **后置条件**：该笔转账结清并写入结算历史；或回退为待确认。
- **主流程**：
  1. 付款方在结算页选择一笔待结清转账；
  2. 输入实际转账金额（≤ 待结清额），点击“已转账”；
  3. 系统生成待确认记录，通知收款方；
  4. 收款方核对后点击“已到账”；
  5. 系统将该笔标记为结清，更新双方余额，写入结算历史。
- **异常流程**：
  - 收款方拒绝：填写原因，状态回退为“待确认”，双方收到通知；
  - 付款方金额超过待结清额：拒绝；
  - 部分结清：剩余金额保留为新的待结清项；
  - 一方退出账本：已确认的结清记录保留，未结清部分按退出规则处理。

### 4.5 UC-06 主动退出账本

- **参与者**：普通成员、Admin
- **描述**：成员在结清后退出账本，立即失去访问权。
- **前置条件**：已加入账本；不是 Owner；净余额为 0。
- **后置条件**：成员移出账本；历史记录保留；操作写入审计日志。
- **主流程**：
  1. 成员进入成员页，点击“退出账本”；
  2. 系统检查净余额；
  3. 余额为 0，弹出二次确认；
  4. 确认后移出账本；
  5. 刷新成员列表，退出者无法再访问。
- **异常流程**：
  - 余额不为 0：拒绝退出，提示先结算；
  - 用户是 Owner：拒绝，提示转让或删除账本；
  - 退出时仍有待确认结算：先完成或撤销待确认记录。

### 4.6 UC-10 申请退款

- **参与者**：记录创建者、Owner、Admin
- **描述**：对一笔未结算支出整单退款，按原分摊比例冲销。
- **前置条件**：原支出未结算、未退款；账本未归档；具备权限。
- **后置条件**：生成退款记录；原支出锁定；余额和统计按净额重算；写审计日志。
- **主流程**：
  1. 在流水详情点击“退款”；
  2. 系统展示退款金额和冲销预览；
  3. 二次确认并填写退款原因；
  4. 系统生成退款记录，按原分摊比例反向冲销；
  5. 原支出标记为“已退款”并锁定；
  6. 通知相关成员。
- **异常流程**：
  - 原支出已结算：拒绝退款；
  - 已退款：拒绝重复退款；
  - 原支出已删除：拒绝退款，提示先恢复；
  - 退款过程中发生并发修改：提示冲突，要求刷新。
